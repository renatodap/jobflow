## 📋 FILE NAMING CONVENTIONS

### Master Files (Root Level)
- **ALL_CAPS.md**: Critical system files
- **START_HERE.md**: Entry point for navigation
- **Clear action words**: TODO, REVENUE, MASTER_PLAN

### Product Folders
- **lowercase-kebab**: product-name/
- **Descriptive names**: feelsharper not fs
- **Version in folder**: feelsharper-v2/ when needed

### Documentation
- **README.md**: In every folder
- **CHANGELOG.md**: For tracking changes
- **API.md**: For API documentation

### Code Files
- **Framework conventions**: Follow Next.js, Python standards
- **Clear component names**: UserDashboard.tsx not UD.tsx
- **Descriptive functions**: calculateMonthlyRevenue() not calc()

## 🔍 NAVIGATION RULES

### Starting Points
1. **New Session**: Always check START_HERE.md
2. **Decision Making**: Reference RENATO_IDENTITY.md
3. **Daily Work**: Check TODO.md
4. **Revenue Focus**: Monitor REVENUE.md

### Cross-References
Every document should include:
```markdown
## 🔗 Related Documents
- Link to parent document
- Links to related systems
- Links to implementation details
```

### Folder README Structure
Every folder must have README.md with:
```markdown
# Folder Purpose

## Contents
- Brief description of each file/subfolder

## Quick Start
- How to use this folder's contents

## Related Systems
- Links to connected folders
```

## 📊 ORGANIZATION METRICS

### Health Indicators
- **Navigation Speed**: Find any file in <3 clicks
- **Redundancy**: Zero duplicate information
- **Currency**: All files updated within 30 days
- **Clarity**: Every file's purpose obvious from name

### Red Flags
- Files in root without clear purpose
- Folders without README
- Dead links in documentation
- Duplicate content across files

## 🔄 MAINTENANCE PROTOCOL

### Daily
- Archive old files
- Update TODO.md
- Check for broken links

### Weekly
- Reorganize misplaced files
- Update folder READMEs
- Consolidate duplicate content

### Monthly
- Full structure review
- Archive unused projects
- Optimize folder hierarchy

## 🚫 PROHIBITED PATTERNS

### Never Do
- Create files in root without approval
- Use unclear abbreviations
- Create deep nesting (>3 levels)
- Leave folders without README
- Store credentials in any file

### Always Do
- Use descriptive names
- Create bidirectional links
- Update parent documents
- Archive before deleting
- Document purpose clearly

## 🎯 QUICK DECISION TREE

```
New File to Create?
├── Is it a master strategy doc? → Root level, ALL_CAPS.md
├── Is it product code? → /active-development/[product]/
├── Is it a template? → /automation-empire/templates/
├── Is it learning material? → /learning-resources/[topic]/
├── Is it tracking data? → /personal-tracking/
└── Is it temporary? → Don't create, use existing files

File to Find?
├── Start with START_HERE.md
├── Check relevant category folder
├── Use search for specific terms
└── Check archive if >30 days old
```
